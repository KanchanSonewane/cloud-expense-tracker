AWS Cloud Lab Architecture & Practical Mapping

How this application fulfills the Cloud Computing Laboratory syllabus

💻 Amazon EC2 (Compute)

Hosts the Express.js application inside a public subnet. Demonstrates virtual machine provisioning, security group firewall rules (Port 80/3000/22), and reverse-proxying.

Mapped to Exp 2

🗄 Amazon RDS MySQL (Database)

Manages users, hashed passwords, and financial transactions. Connects securely with the EC2 compute instance using parameterized SQL queries and managed automated backups.

Mapped to Exp 11

☁ Amazon S3 (Object Storage)

Receipts (PNG, JPG, PDF) are stored in a dedicated S3 bucket rather than bloated database BLOBs. Presigned signed URLs allow secure browser viewing without making the bucket public.

Mapped to Exp 4

🕒 S3 Versioning (Data Protection)

Object versioning keeps historical revisions of overwritten or updated receipts. Protects against accidental file deletion and demonstrates rollback to earlier versions.

Mapped to Exp 5

🔒 AWS IAM (Least Privilege)

The EC2 instance authenticates to Amazon S3 using an IAM Instance Profile (IAM Role) eliminating hard-coded credentials from source code or config files.

Mapped to Exp 12

🌐 Amazon VPC (Network Isolation)

Configured with an Internet Gateway, public subnets for the web tier, and private subnets for the RDS database tier, securing database access from public internet intrusion.

Mapped to Exp 8

🚀 Quick Viva & Lab Demo Instructions

  1. Log in using the demo account: demo@cloudlab.edu (Password: Demo@1234) or create a new user.
  2. Add an expense or income entry with an attached receipt (JPG/PNG/PDF).
  3. Inspect the stored transaction metadata in Amazon RDS and receipt file in Amazon S3.
  4. Edit the transaction and upload a revised receipt to inspect S3 Object Versioning.
  5. Click "Cloud Lab Info" on the dashboard to view real-time cloud diagnostic telemetry.
